### B2. Corrupted LaTeX escapes on page 1, inside Contribution 1
`tex/main.tex:194–200` contains **literal control characters** where commands should be —
`\times` was written as TAB+`imes` (3×) and `\ref` as newline+`ef` (2×). The compiled PDF
renders:

> "the range is 3.4–12.2𝑖𝑚𝑒𝑠, and the 11.4 M tier alone spans 2.8–11.0𝑖𝑚𝑒𝑠. Accuracy
> does not track parameter count over a 28-fold range — model size is not the bottleneck
> **(Sections efsec:flat–efsec:desc)**."

LaTeX does not warn on either form: `ef{sec:flat}` is ordinary text, so no "undefined
reference" is emitted and `check_tex_refs.py` will not catch it. This is the first
technical content an editor reads.

Verify after fixing:
```
python - <<'EOF'
raw = open(r"docs/paper/tex/main.tex","rb").read()
assert b"\times" not in raw and b"\ref" not in raw.replace(b"\\ref",b"")
EOF
```
(Simplest check: the file should contain **zero** TAB bytes.)

## Major

### C1. The control-arm confidence interval uses the wrong replication unit
This is the paper's headline novelty and the one finding that changes a conclusion.

§5.3 / abstract / highlights: *"a mean of +1.96 points with a 95 % confidence interval of
[+1.70, +2.22] over encoders."*

That interval is the *t*-interval over **four encoder means** (n=4, df=3) — it reproduces
exactly. But the four encoders are scored on **the same 7 descriptor seeds** and the same
11,337 images. The seed is the randomised unit; the encoders are four readouts of it, not
four independent replications. Recomputed from
`zeroshot_eval_C_paired_ungseeds.json`:

| replication unit | n | mean | 95 % CI |
|---|---|---|---|
| encoders (as published) | 4 | +1.96 | **[+1.70, +2.22]** |
| seeds (diff averaged over encoders) | 7 | +1.96 | **[−0.23, +4.14]** |

Per-seed mean differences: `+0.69, +1.20, −1.56, +5.66, +1.12, +3.98, +2.63` — one seed is
negative and one is +5.66. Within-encoder paired *t* values are +1.37, +3.44, +3.21, +1.11.

The published interval (width 0.52 pp) is narrower than the seed-to-seed SD (2.36 pp)
because seed noise was averaged away *before* the interval was formed. Any reviewer with
the released JSON reproduces this in ten lines.

Also: the stated within-encoder range *"between 1.3 and 2.6 standard errors"* is computed
with the **independent-samples** SE (1.53/2.42/2.55/1.30) on a **paired** design. The
paired values are 1.11–3.44.

What is defensible on this data: *sourcing does not measurably cost accuracy, and the
point estimate is positive on all four encoders.* That is exactly the paper's thesis —
grounding buys auditability, not accuracy — so the honest version costs you nothing. What
is not defensible is a CI excluding zero. On the full 51 classes both analyses already
include zero (encoder [−0.68, +2.55], seed [−0.52, +2.39]); §5.3 reports +0.94 there with
no interval at all.

`control_arm_statistics.json` also stores `"equivalence_bound": 2.2163`, which is just the
CI upper limit renamed. A TOST bound must be pre-specified, not read off the result.

### C2. Contribution 5 contradicts the Results twice
> "naive fine-tuning causes catastrophic forgetting … and a leave-one-crop-out analysis
> shows the held-out crops **are not cherry-picked**."

Both halves are walked back later in the paper:

- **Cherry-picking.** Table 6 + §5.6: held-out crops average **19.0 %** against **9.0 %**
  for the trained pool, with non-overlapping CIs (Orange [26.4, 31.3] vs Corn [4.4, 5.3]).
  §5.6 honestly retreats to "we do not claim the held-out set is adversarially hard."
  The contribution bullet still claims the control passed. It did not — it argues the
  other way.
- **Forgetting.** §4.5: "even naive fine-tuning **does not destroy** cross-crop transfer
  here: unseen accuracy settles at 16.4 %, still 8.4 times chance." Figure 7 goes further
  and annotates α=1 (full fine-tune) as **"best seen+unseen"** — labelling naive
  fine-tuning optimal in the paper whose architecture is a frozen backbone.

Contributions 1 and 2 were re-verified on 2026-09-08; bullet 5 was not.

### C3. The "coverage dilution" mechanism is contradicted by your own released data
§5.3, explaining why +1.96 halves to +0.94:
> "on the ten classes only one arm filled, **both arms are reading the same fallback
> text**, which can only move the difference toward zero."

From `paired_stats.dropped`, all ten classes were dropped because **`grounded_matched`**
failed at ≥1 seed (Coffee/Berry_Blotch, Coffee/Phoma, three Wheat Resistance_Phenotype
labels, …). `ungrounded` filled 51/51 at every seed. So on those ten classes the arms read
**different** text: ungrounded reads its own generation, grounded falls back to the
keyword bank. They cannot be "reading the same fallback text", and the difference is not
mechanically pulled to zero — it is a real loss.

The honest reading is less flattering and more interesting: *where grounded generation
fails, its bank fallback loses to ungrounded generation.* Coverage failure is a deployment
cost of the grounding constraint, which is a genuine finding and pairs naturally with the
over-refusal limitation you already disclose.

### C4. "At or below chance" is false for BioCLIP2
§5.2 and Related Work: *"Biological and domain leaf-disease foundation models perform at or
below chance under a descriptor protocol"* / *"find they do not transfer."*

From `run_all_bakeoff.json` (17 classes, chance 5.88 %):

| model | acc | × chance |
|---|---|---|
| BioCLIP2 | 9.58 % | **1.63× — above chance** |
| SCOLD | 4.39 % | 0.75× — below |

Only SCOLD is at/below chance, and that is the model you already describe as a best-effort
wrapper you rest no claim on (`make_figures.py:54` comments it as a broken RoBERTa
fallback). So the one faithfully-evaluated domain model is clearly above chance — much
worse than the CLIP tiers (22–31 %), but not "at or below chance". Fig. 5 plots the chance
line, so this is checkable at a glance. "Do not transfer competitively" is supportable.

### C5. §7 "Scope and variance" contradicts §5.3
> "Results use a **single random seed** on a single evaluation machine; apart from the
> leave-one-crop-out bootstrap intervals **we report no variance estimates**."

§5.3 reports seven seeds, per-encoder standard deviations and a 95 % CI. Stale paragraph
that survived the control-arm addition; it reads as though the authors forgot their own
central experiment.

### C6. Literature grounding is thin for this venue
20 references, all cited, none orphaned (bibliography hygiene is clean). But for a CEA
special issue on foundation models in agriculture, roughly three are agricultural
(SAGE, PlantVillage, bouacida2025). There is no engagement with agricultural
disease-detection literature, field-deployment/edge-agriculture work, or other
agricultural VLM efforts. An editor screening for fit will notice before a reviewer does.

## Moderate

**D1 — The abstain gate is over-sold.** Contribution 3 and the abstract say the gate
"makes the modest top-1 field-useful". From Table 3, discarding the least-confident 20 %
of images buys:

`A: +1.8 +4.4 +1.1 +2.2 | B: +1.8 +3.6 +0.9 +2.1 | C: +2.1 +2.9 +0.8 +2.4` — mean **+2.2 pp**.

Top-1 goes from ~24 % to ~26 % while refusing one image in five. AURC sits at 0.62–0.74.
The gate is correctly *ordered* (which is all §5.4 actually demonstrates) but its effect
size is near-negligible; top-5 (59–77 %) is what carries field-usefulness. Claim the
ordering and the shortlist, not the gate.

**D2 — §5.4's central comparison is not shown anywhere.** "at the largest label space it
holds the highest top-5 on all four deployable encoders and the lowest AURC on three of
them" is *true* (I verified: top-5 4/4, AURC 3/4 at C; 2/4 and 1/4 at A) — but Table 3
prints **only** the grounded strategy, so no reader can check it. Add rich columns.

**D3 — Bake-off claims contradict Table 2 without a protocol fence.** §5.2: "The 11.4 M
encoder … *beats* the larger 21.5 M model." In Table 2 the 21.5 M model is *higher* at
every configuration (A 28.6 vs 17.6; B 25.6 vs 20.5; C 24.0 vs 21.6). The claim is true on
the 17-class pilot (27.0 vs 22.4) but §5.1 fences Protocol P only for the distillation
sentence; §5.2 carries no fence at all.

**D4 — The 28× flatness result is also Protocol P.** The ten-encoder survey
(`make_figures.py:28–39`) is the 17-class pilot. Contribution 1 places "does not track
parameter count over a 28-fold range" beside nested-split numbers with no fence, and the
Conclusion repeats it. The abstract gets this right (7.6-fold, 11.4–86.3 M) — so abstract
and contributions disagree about the same claim's scope.

**D5 — Three different values for one parameter range.** §5.1 "11–322 M … 28×"; Fig. 3
caption "27-fold parameter range"; Conclusion "11.4–304 M". The data says 11.41–321.78 M =
28.2×.

**D6 — WiSE-FT is not a monotone dial.** Table 4 / Fig. 7: seen 59.0 → 56.0 → 60.3 → 67.7
→ 81.5; unseen 21.6 → 14.8 → 15.5 → 18.4 → 16.4. **Both** columns are non-monotonic —
α=0.75 beats α=0.25 on seen *and* unseen. §4.5 hedges the seen column ("head-refit noise")
but not the unseen one, and still calls it "one tunable knob". One encoder, one seed. Also
the caption says α=0 reproduces 58.8 % while the table row reads 59.0 %.

**D7 — The averaging convention is never stated.** Nothing says whether accuracy is
image-weighted (micro) or class-averaged (macro), on a capped, imbalanced 51-class set
where it matters. I checked, and the scaling claim survives: macro-over-crop gives
21.9 / 23.8 / 23.9 against micro 21.5 / 22.7 / 23.9 — still monotonic. So this is a
reporting gap, not a broken result. State it, and consider adding macro-F1; CEA reviewers
routinely ask for per-class metrics on imbalanced problems.

**D8 — Table 5 mixes units silently.** Columns are `Torch FP32 | ONNX FP32 | INT8 dyn. |
INT8 static | FP32 | INT8` — the first four are ms, the last two MB, all with identical ↓
arrows and no unit in the header. `MobileCLIP-B … 345.55` reads as latency. Put units in
the header.

**D9 — The headline ×chance range is the flattering construction.** "2.2–13.9× chance"
takes the minimum at A (6.25 % chance) and the maximum at C (1.96 % chance) — the top of
the range is driven by the denominator shrinking as the label space grows. Against the
majority-class prior you already report (14.8 % at A, 4.2 % at C) the same result is
≈1.5–5.7×. §5.4 makes this point well; the abstract, Contribution 1, Conclusion and
Highlight 1 all still lead with the ×chance form. This is the same error class you already
corrected once (the 29–38× top-5 figure).
